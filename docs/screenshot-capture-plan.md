# スクリーンショット撮影指示

**別エージェントが自動撮影する前提。** 画面遷移・タップ対象・入力する式を具体的に書く。
**対象は6言語すべて（en / ja / es / pt-BR / de / fr）。** 以前は日英だけ撮って他4言語には英語版を流用していたが、
掲載文だけ言語ごとに書き分けても、一覧に出る画像が英語のままではその言語のユーザーには「英語のアプリ」に見える。

**画像は翻訳ではなく、言語ごとに写す中身を変える。** どのノート・どのサンプルを開くかは
`docs/target-users-by-locale-2026-09.md` 第1節のターゲットに合わせてあり、
`scripts/capture-submission-assets.mjs` の `NOTEBOOK_TARGETS` と `LABELS[].examCategory` / `searchQuery` が情報源:

| 言語 | ノート系カット（06・07）で開くノート | サンプルのタブ（14） | 検索語（13） |
|---|---|---|---|
| en | High school physics → Mechanics → Uniformly accelerated motion | Exam prep | solar |
| ja | 電気・エネルギー → 電気の基礎計算 → 電圧降下と必要な電線の太さ | 試験対策（電験・電工） | 太陽光 |
| de | Elektrizität & Energie → Praktische Elektrotechnik → Spannungsfall und der nötige Leiterquerschnitt | Klausur & Prüfung | Spannung |
| es | Física (bachillerato) → Electricidad → Campo eléctrico y potencial de una carga puntual | Preparación (EBAU) | campo |
| pt-BR | Física (Ensino Médio) → Eletricidade → Campo elétrico e potencial de uma carga pontual | Preparação (ENEM) | tensão |
| fr | Physique (lycée) → Mécanique → Mouvement uniformément accéléré | Révisions (physique-chimie) | masse volumique |

カテゴリカードの並び自体も `lib/locale-relevance.ts` で言語ごとに変わるので、カット5（カテゴリグリッド）と
カット14（サンプル）は**操作が同じでも言語ごとに違う絵になる**。

## 共通の準備

- 端末: Android実機またはエミュレータ、縦向き（portrait）
- テーマ: ライトモード（既存の店頭素材と統一するため。ダークモードは今回の撮影対象外）
- 解像度: Google Playの推奨1080×1920px相当が撮れるデバイス／エミュレータ設定を使う（`docs/android-submission-checklist.md`の2番を参照）
- 言語切替: 設定タブ → 「Language / 言語」セクションでen/jaを切り替える（`app/(tabs)/settings.tsx`、`APP_LANGUAGES`の並びで表示）
- 各カットの前に、指定されたデータ投入・式入力を行ってから撮影する（空の初期状態のまま撮らないこと。プリセットは初回起動時に自動投入されるので、計算ノート関連のカットは追加操作不要）

## カット一覧（優先順）

### 1. 電卓画面 — 基本の単位付き計算（最重要・1枚目候補）

- 画面: 電卓タブ（タブバー1番目、関数アイコン）
- 操作: 入力欄に `5cm + 1mm` と入力する
- 期待する見え方: 結果カードに `5.1 cm` 相当の値、SI基準値、単位チップ列が表示されている状態
- 撮影タイミング: `=` を押す前でもリアルタイムに結果が出る（`previewCalculatorInput`の仕様）ので、`=`前後どちらでも良いが、`=`を押して履歴に残った状態で撮ると次のカットに繋げやすい

### 2. 電卓画面 — 次元検証エラー

- 操作: 入力欄を `5m + 1kg` に書き換える
- 期待する見え方: 「計算できません」系のエラー表示（次元不一致）。正常な結果ではなくエラー状態そのものを写す

### 3. 電卓画面 — 単位比較表

- 操作: `100km / 2h` のような速さの式を入力し、結果カード下の「単位を比較」（`compareUnits`）をタップして展開する
- 期待する見え方: 単位チップ列の下に、比較表の行（複数単位への換算結果一覧）が開いた状態
- コード上の目印: `app/(tabs)/index.tsx`の`showComparison`トグル、アクセシビリティラベルは`copy.compareUnits`（英語表示は"Compare units"）

### 4. 電卓画面 — 進数（2進・8進・16進）

- 操作: 入力欄を一度クリアし、単位付けレールの `0x` ボタンをタップして進数入力モードに入る。適当な16進の値（例: `1F4`）を入力する
- 別カットとして: 単位無しの整数（例 `500`）を通常入力し、結果カード下に出る `DEC/BIN/OCT/HEX` の表示用チップ列も撮る（`BASE_META`のラベルがそのまま表示される）
- 期待する見え方: `0x`ボタンからの導線が分かるカット（レール上のボタンが見えている状態）と、進数の表示チップが切り替わった状態の両方があると良い
- 注意（CLAUDE.md 165行目）: 進数は単位ではなく「同じ値の表記」を変えるだけの機能。単位チップと混同されない構図で撮る

### 4a. 電卓画面 — 厳密値表示（分数・π・√）

- 操作: 入力欄をクリアし、`2*pi*50` と入力する（他に厳密な形が出る例: `1/3` → 分数1/3、`10/4` → 5/2、`sqrt(8)` → 2√2、`atan(1)`。整数になる式では出ないので使わない）
- 期待する見え方: 結果カード上部の「小数 ⇔ 厳密値」チップ（英語表示は`Decimal`/`Exact`、日本語は`小数`/`分数・π`）が両方見えている状態。「厳密値」側を選び、KaTeXで組版された本物の分数・根号（このカットでは`100π`のような表記）が出ている画面を撮る
- コード上の目印: `app/(tabs)/index.tsx`の`decimalForm`/`exactForm`ラベル、`lib/exact-value.ts`の`findExactValue`
- 注意: 進数チップとは排他（厳密値が出るのは非整数の値のときだけ）なので、カット4と同時に出ることは無い

### 5. 計算ノート — カテゴリグリッド（幅を見せる）

- 画面: 「ライブラリ」タブ（タブバー3番目、しおりアイコン。`t("constants")`="Library"）
- 期待する見え方: カテゴリグリッド一覧（理科（小・中）・高校物理・化学の量的関係・天体宇宙・電気・エネルギー・趣味/ものづくり・暮らし・車/自転車の物理・機械/構造設計の最上位9枚、38カテゴリ・194件）。初期状態のまま追加操作不要
- 補足カット: 「高校物理」のような親カテゴリをタップし、サブカテゴリ（力学/熱/波動/電気/原子）に降りた2階層目の画面も1枚

### 5a. 計算ノート — 検索

- 画面: 「ライブラリ」タブ上部の検索欄（プレースホルダは英語`Search all notebooks`、日本語`すべての計算ノートを検索`）
- 操作: 検索欄に日本語なら「密度」、英語なら`density`のようにヒットする語を入力する
- 期待する見え方: カテゴリ階層に関係なく該当ノートが横断で一覧表示され、各カードにカテゴリ名が添えられている状態（`app/(tabs)/constants.tsx`の`notebookSearchResults`・`searchResultCategoryLabels`）
- コード上の目印: `lib/notebook-search.ts`

### 6. 計算ノート — LaTeX数式表示（見栄えの良いもの）

- 操作: ライブラリ → 機械・構造設計 → 「はり・柱」（旧・材料力学、PR #46で作り直し） か 高校物理のいずれか見栄えの良いノート（例: はり・柱の梁のたわみ、または物理の運動方程式）を開く
- 期待する見え方: KaTeXで組版された本物の数式カードが表示されている状態。手順の結果欄が等式（例: `F = m*a`）になっていることが分かる構図
- 遷移: ライブラリ → カテゴリ → サブカテゴリ（「はり・柱」は「機械・構造設計」の子カテゴリ）→ ノート一覧 → 該当ノートをタップ

### 7. 計算ノート — 実際に使ったものタブ

- 画面: 「ノート」タブ（タブバー2番目、開いた本のアイコン。`t("notebook")`="Notebooks"）
- 前提操作: カット6で開いたノートがそのまま「最近使ったノート」として表示される状態
- 期待する見え方: ノート詳細（固定ヘッダー: 戻る・ピン留め・編集、固定フッター: 保存バー）

### 8. ユーザー定義単位（自作単位）

- 画面: 「設定」タブ → 「自作の単位」セクション（`t("customUnits")`="Custom units"）
- 操作: 記号 `shaku`、定義 `0.303m` を入力して追加ボタンを押す（既存の単位と衝突しない記号を使うこと）
- 期待する見え方: 追加後、一覧に登録した自作単位が表示されている状態
- 補足カット（余裕があれば）: 電卓タブに戻り、`3shaku`のように登録した単位を使った式を入力し、計算できている様子

### 9. Pro画面

- 画面: 「設定」タブ内のPro導線、またはProタブ（タブバーからは隠れているが`settings`等からリンクあり）
- 期待する見え方: `app/(tabs)/pro.tsx`の4特典カード（Ad-free / CSV export / My unit sets / Notebook sharing）が見えている状態。価格ボタンはWeb版だと「web preview」注記が出るので、**Android実機で撮影すること**（Web版だと購入ボタンの見え方が異なる）

### 10. バックアップ／復元（余裕があれば）

- 画面: 「設定」タブ → 「バックアップと復元」セクション
- 期待する見え方: 計算ノート・グローバル定数のバックアップ書き出し／取り込みのUIが見える状態

### 11. サンプルシート — その国の試験名で出るカテゴリタブ

- 画面: 電卓タブ → 「サンプル」（`copy.samples`）
- 操作: 先頭のタブ（言語ごとに Klausur & Prüfung / Preparación (EBAU) / Preparação (ENEM) / 試験対策（電験・電工） …）を選ぶ
- 期待する見え方: タブの並びが言語ごとに違い、その国で実際に受ける試験の名前が先頭に出ている状態
- **言語ごとの差が1枚で一番よく伝わるカット。** 掲載時は上位に置くこと

### 12. 電卓画面 — 接頭語の打ち消し

- 操作: `4.7kΩ × 2mA` を入力して `=`
- 期待する見え方: `9.4 V`。k と m が打ち消えて V になることが読み取れる状態

## 各カットの言語別セット

上記14カット（1〜12＋4a・5a）を6言語すべてで撮影する（操作は共通、開くノートと検索語だけ上の表のとおり言語ごとに変える）。

**カットの見出し数と書き出されるファイル名は1対1ではない。** `submission-assets/screenshots/` に入るのは**1言語あたり16枚**（＝計96枚）で、対応は次のとおり:

| このドキュメントのカット | 書き出されるファイル |
|---|---|
| 1 / 2 / 4 | `01-calc-basic` / `02-dimension-error` / `04-number-base` |
| 3（単位比較表） | `03-speed` と `03-compare-units` の**2枚** |
| 4a（厳密値） | `10-exact-fraction` / `11-exact-pi` / `12-exact-sqrt` の**3枚** |
| 5 / 5a | `05-library-grid` / `13-notebook-search` |
| 6 / 7 / 9 | `06-notebook-list` / `07-notebooks-tab` / `09-pro` |
| （見出し無し） | `08-settings`（設定画面の言語一覧。対応6言語が見える状態） |
| 11 / 12 | `14-exam-samples` / `15-prefix-cancel` |
| 8（自作単位）・10（バックアップ／復元） | **未撮影**（旧素材にも無く、必要になったら足す） |

ファイル名の情報源は `scripts/capture-submission-assets.mjs` の `SHOTS` 配列で、`submission-assets/README.md` の一覧もこの16枚に合わせてある。**番号はファイル名の識別子であり、このドキュメントのカット番号とは独立**（既存素材の命名を保つため振り直していない）。

## 注意点

- Web版で先行して構図確認するのは構わないが、**Pro画面・購入導線は必ずAndroid実機/エミュレータで撮る**（web preview注記が出ないようにするため）
- 別エージェントが実装中の「Web版Proプレビュー」機能はスクリーンショット撮影の対象外（審査員向けの動作確認専用。`docs/reviewer-testing-instructions.md`参照）
