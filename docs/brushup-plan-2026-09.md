# ブラッシュアップ方針（2026-09-08）: 「検算する電卓」に寄せる

最新のmain（`9e644bd`）を起点に、競合の最新UI・ターゲットユーザーの痛み・実機UX監査の3本を並行調査し、
「電卓というレッドオーシャンで誰に何で刺すか」を決め直した記録。調査の生データは
`docs/market-research-2026-09.md`（前回）に加えて本稿末尾の要約を参照。

## 調査の限界

3本ともegressプロキシで App Store / Google Play / Reddit / 知恵袋 / note などの直接取得が塞がれており、
引用は検索スニペットと二次情報経由。**[確認]**（ソースに明記）と **[推測]** を本文で区別している。

## 1. 結論

### ターゲット

| 優先 | 誰 | 決定的な瞬間 | 根拠 |
|---|---|---|---|
| **メイン** | **電気系の学習者・受験者**（電験三種・第二種電気工事士・危険物乙4）＋電子工作/DIYソーラーのホビースト | 過去問・発注前の検算で **k/m/μ と 10³ を暗算で混ぜて桁を落とす**。「kは接頭語、Kはケルビン」「余計な0の入力を省く」 | 痛みの言語化が最も具体的 [確認]。電工二種は年20万人超、乙4も約20万人/年 [確認]。「単位を検算する道具」の競合が無い |
| サブ1 | 理工系の大学1〜2年（実験レポート） | mL→m³・g/cm³→kg/m³ を揃えて有効数字で書く。「単位が抜けていたり誤った単位を書くと減点」 [確認] | 週1本で頻度が高く6言語で普遍。Wolfram のモバイル体験が弱い（Android 3.7★ / iOS 2.7★）[確認] |
| サブ2 | 機械・建築のジュニアエンジニア（手計算チェック） | Mathcad の units チェック（"acts as a check—if you're accidentally working with mixed units, it lets you know"）をポケットに | WTP最高。Qalculate Android は F-Droid 限定で2026年9月以降インストール不可の可能性 [確認]、Frink はREPL寄り |

**非推奨**: 高校生単独（WTP低・入試持込不可）、教師・親（探索行動の証拠が薄い）、コーヒー/自転車/写真（単目的アプリで飽和）。

**制約 [確認]**: 日本の入試・国家資格試験はスマホ電卓の持込不可。JTBDは「試験本番」ではなく**学習中の検算・レポート・現場**。

### 差別化の一言

> **単位ごと計算し、桁と次元の間違いをその場で教える電卓。** `12V / 4.7kΩ` と打てば `2.55 mA`。`3m + 2kg` は計算しない。

競合調査で「プリセット公式ノート＋ライブ次元検証」をモバイルで組み合わせた新規参入は2025–26に見つからなかった。
一方 Soulver 4（2026-06、$59買い切り、iOS/Macのみ）は答えのトークン化と単位定義シートを、
Numbat は導出単位の自動簡約と人間語の次元エラーを実装済み。**エンジンは負けていないのに、見せ方で負けている**のが現状。

### UX監査で分かった「見せ方の負け」

実機（Web export + Playwright、390×844）で確認した、中核価値を隠している問題:

1. **次元エラーがリアルタイムでは見えない。** `3m + 2kg` と打っても結果カードは「式を入力すると結果が出ます」のまま。`=` を押した人だけ赤帯を見る。リアルタイム計算の設計なので、**多くの人は一度もこのアプリの最大の売りに遭遇しない**。
2. **答えがユーザーの単位で出ない。** `5cm + 1mm` → `0.051 m`。cm は en-US のチップ列で8番目＝画面外。「電卓が勝手に単位を変えた」が第一印象になる。
3. **前の表示単位が引き継がれて誤爆する。** 長さ計算の後に `255` や `1/3` を打つと「cmへ変換できません」の赤字が出て、進数チップも消える（到達不能）。
4. **`12V/4.7kΩ` は `0.00255 A`。** メインターゲットの痛みそのもの（接頭語）に対して、答えを読みやすい接頭語で出さない。
5. **結果値が28pxで、その下に13pxのチップが3行。** 結果が「数字の多いカードの一部」に埋没する。一般的な電卓は結果40〜56px。
6. 空状態に145px（画面の17%）の空白があり、その中に「サンプル」「数学」の小ボタンが浮いている。
7. 細部: 設定の言語チップが重なって読めない（全言語で再現）／オンボーディング3枚目が空の「ノート」タブへ誘導／`Decimal / Exact` が `0.051` にも出て「押しても意味のないボタン」になる。

### 見送ったもの（理由つき）

- **タブの再編（Library→Notebooks 等）**: 提出資料・スクショ28枚・デモ動画が全部タブ名に依存している。Shipaton締切（9/30）直前に資料を作り直すコストが大きい。公開後に。
- **ノート入力欄の「記号＝値＋単位▾」3分割**: `notebook-detail.tsx` と PDF エクスポートの `resolveNotebookStepDisplay` の両方に波及する。効果は大きいが別PRで。
- **試験別ノート束（電験三種・電工二種・乙4）**: カテゴリIDの追加＝既存ユーザーへの再投入になるうえ、中身は既存ノートの再編なので重複投入の問題（CLAUDE.md「カテゴリIDは変えない」）に触れる。ストア掲載文とサンプルカテゴリで表現する方が安全。
- **接頭語の入力補助（`4.7k` → kΩ/kV を提案）**: `lib/unit-input.ts` の候補ロジックに手が入る。P0-2で「出力側」の接頭語は解決するので、入力側は次に。
- **答えのトークン化（Soulver 4 方式）・双方向ソルバー・AI翻訳**: いずれも中〜大。差別化としては魅力的だが今回のスコープ外。
- **Ohm→Ω の表示統一、`mn` の候補に min/mm が出ない件、比較表の `au`/`ly` の雑音、10桁表示**: 小さいが独立した修正なので別PRにまとめる。

## 4. 調査の要約

### 競合（2026-09-07）

- **Soulver 4**（2026-06-25）: 答え→青いトークンとして挿入・連動更新、Definitions sheet（変数と単位）、木工向け分数丸め、$59買い切り、Android なし [確認]。
- **Numbat**（Insect後継）: 次元を型として静的検査、v1.23で `J/s → W` の自動簡約、暗黙乗算エラー文の改善。Tauri製アプリは26 stars [確認]。
- **Qalculate Android**: Google の開発者認証方針で2026年9月以降インストール不可の可能性を明言 [確認]。
- **CalcNote は2025-11にサブスク化**→「買い切りが欲しい」「復元問題」に不満集中。Construction Master Pro も同様 [確認]。→ 買い切りは訴求点として明示する価値がある。
- **PTC の実証**: ChatGPT が `3 ft 1/8 in → cm` で4回連続誤答 [確認]。「AIは入力の翻訳、計算は次元解析エンジン」の位置が説得力を持つ [推測]。
- **日本市場**: 評価軸は「広告なし」「履歴」「数式表示・編集」。Panecal「広告がキーを隠す」。坪・畳（京間/江戸間/団地間）・尺・寸の需要 [確認]。
- **プリセット公式ノート＋ライブ次元検証をモバイルで組み合わせた新規参入は見つからなかった。**

### ターゲットユーザー（2026-09-07）

- 教師ブログ「計算の『単位換算』でつまずいてしまう生徒がちらほら」「速度や密度の単位変換は物理の本質というより『技術的な処理』なのに、ここで混乱」 [確認]
- 電験三種「倍数を表す接頭語を覚えると、計算中の桁間違えを予防できたり」「余計な『0』の入力を省くことが、桁数ミスを防ぐ最善策」 [確認]
- 乙4「問題が『mL』で答えが『L』なら、1,000で割る一手間を忘れないこと、設問と選択肢の単位を最初に丸で囲む癖」 [確認]
- 英語圏「forgot to change units into SI units」「dividing by 100 instead of 1000」「units are part of the answer, not an optional extra」 [確認]
- 支払い: RealCalc Plus「bought the premium version just to support the developer」、Panecal「ソッコーで有料版を買った」、Soulver iPhone $14買い切り。払う理由は「信頼できる結果」「買い切り・オフライン」「その計算が速い」 [確認]
