# Android（Google Play）提出チェックリスト

**対象は Android のみ。** iOS/App Store 向けの手順は含まない（今回の提出範囲外という前提でユーザーが確定済み）。
確信が持てない数値には**「要確認」**を明記した。Google Play Consoleの実際の画面で数値を再確認してから作業すること（本ドキュメントの作成時点=2026年9月、Web検索による調査）。

## 実際に手を動かす順番

### 1. Play Console のアプリ登録・基本情報

- [ ] Google Play Console でアプリを新規作成（パッケージ名 `com.app.siunitcalculator` — `app.config.ts`の`androidPackage`実測値）
- [ ] アプリの言語をデフォルト（英語）に設定し、後述の5言語（ja/es/pt-BR/de/fr）を追加言語として登録
- [ ] Data safety フォームの入力（後述の3番を参照）
- [ ] 広告の有無の申告（後述の4番を参照）— **必ずコンテンツレーティングより前に申告する**（申告前だとレーティング質問票に進めない）
- [ ] コンテンツレーティング（IARC）質問票への回答（後述の5番）

### 2. ストア掲載情報（Main store listing）

- [ ] アプリ名・短い説明・詳しい説明を6言語ぶん入力（`docs/store-listing-copy.md`からコピー）
  - 短い説明: **上限80字**（要確認: Play Consoleの実際の入力欄で文字数警告が出ないか確認）
  - 詳しい説明: **上限4,000字**（同上、要確認）
- [ ] アプリアイコン: **512×512px, 32-bit PNG**（アルファチャンネルあり可）。角丸・影は自分で付けない（Play側が自動適用）。安全余白は内側15〜18%目安
- [ ] フィーチャーグラフィック（Feature graphic）: **1024×500px, JPEGまたは24-bit PNG（アルファチャンネル不可）**。**iOSには無い項目なので新規に作る必要がある。** `docs/submission-assets-review.md`に既存の店頭アイコン素材からの作成方針あり
- [ ] スマートフォンのスクリーンショット: **最低2枚・最大8枚**。JPEGまたは24-bit PNG（アルファチャンネル不可）、各辺320〜3840px、アスペクト比は最長辺:最短辺が最大2:1。推奨解像度は1080×1920px（要確認: Play Consoleの現行UIでの正確な下限/上限）
  - 日本語・英語の2言語ぶんのみ実際に撮影し、他4言語（es/pt-BR/de/fr）の掲載ページには英語版スクリーンショットを流用する（今回の前提）
- [ ] 7インチ／10インチタブレット向けスクリーンショットは**今回は用意しない**（電卓アプリでタブレット最適化していないため。Play側は必須ではない）

### 3. Data safety（データセーフティ）フォーム

このアプリが実際に組み込んでいるSDK（`package.json`実測）を根拠に、以下を申告する:

| 項目 | 現状の実装 | 申告の方向性（要確認） |
|---|---|---|
| ローカル保存のみのデータ（計算履歴・定数・自作単位・設定） | サーバーに送信しない。端末内AsyncStorageのみ | 「データを収集していません」寄りで良いはずだが、下記のAdMob/RevenueCatの分は別途申告が必要 |
| 広告（`react-native-google-mobile-ads`使用） | AdMobバナー広告のみ（全画面広告は無し） | Googleの公式ガイダンスでは広告ID・デバイスID等を「デバイスまたはその他のID」として申告するよう明記されている。**要確認**: 現在の実装がどのAdMob機能（パーソナライズ広告か否か）を使っているかによって申告内容が変わる |
| 課金（RevenueCat経由） | 購入履歴・アプリ内でのユーザー識別子をRevenueCatのバックエンドと連携 | 「購入履歴」の収集・第三者共有として申告が必要な可能性が高い（要確認: RevenueCat公式のData safety記入例を確認すること） |
| プッシュ通知権限（`POST_NOTIFICATIONS`、`app.config.ts`) | 現状コード内に通知送信のロジックは見当たらず、テンプレート由来の権限が残っている可能性がある | **要確認**: 実際に通知を送っていないなら権限自体の削除を検討。送るなら何のためかをこのタイミングで洗い出す |

**申告の原則**: 「実際に何を収集しているか」だけを書く。サードパーティSDK（AdMob・RevenueCat）が収集するものも自社の収集として申告義務がある（Googleの公式見解）。

### 4. 広告の申告

- [ ] 「このアプリには広告が含まれています」を選択（AdMobバナー広告があるため）
- [ ] コンテンツレーティング質問票より**前に**この申告を完了させること（順序が逆だと質問票に進めない）

### 5. コンテンツレーティング（IARC）

- [ ] Play Console内の質問票に回答し、IARCレーティングを取得する
- [ ] 電卓・教育アプリのため暴力・性的表現等は無し。広告表示ありと正直に回答する
- [ ] アプリ内容（数式・単位計算）を変える更新のたびに質問票を再確認する義務がある（今回のような大型アップデートは要再確認）

### 6. 買い切り課金（非消費型）のPlay Console側の設定

**Google PlayにはApp Storeのような「非消費型（Non-Consumable）」という商品区分は無い。** Play Consoleの「アプリ内アイテム（in-app products / managed products）」は元々「消費（consume）」を呼ばない限り再購入不可の一回限りの商品として扱われる。以下の手順で設定する:

- [ ] Play Console → 収益化 → 商品 → アプリ内アイテム で新規の「マネージドプロダクト（managed product）」を作成（例: `pro_lifetime`）
- [ ] 価格を設定（`docs/market-research-2026-09.md`第4節の$24.99〜29.99案などを参考に、地域別価格はRevenueCat/Playの自動換算に任せる）
- [ ] RevenueCatダッシュボード側で、この商品を**Non-Consumable**として登録し、`pro` entitlementにアタッチする（`lib/revenuecat-provider.tsx`・`lib/purchase-offering.ts`の実装が前提とする構成）
- [ ] **アプリ側が誤って「消費（consume）」APIを呼んでいないこと**を確認（消費すると再購入可能になり、買い切りの意味が壊れる）。CLAUDE.mdに明記の通り、このアプリはRevenueCat SDK経由の標準的な購入フローのみを使っており、独自のconsume呼び出しは無い前提（`lib/revenuecat-provider.tsx`を参照して裏取り済みか、着手時に再確認すること）
- [ ] Play Console側で、この商品にライセンステスト用アカウント（クローズドテストのテスター）を割り当て、無料でテスト購入できるようにする

### 7. クローズドテスト（該当する場合）

`docs/market-research-2026-09.md`第7節の通り、2023年11月13日以降に作成された個人アカウントは**本番公開前に12人以上のテスターで14日間連続のクローズドテスト**が必要（Google Play Console公式の規則。要確認: このプロジェクトのデベロッパーアカウントの作成日と該当有無）。

- [ ] 該当する場合、テスターを12人以上確保しクローズドテストを開始する
- [ ] 14日経過後、本番公開に申請する

### 8. プライバシーポリシーと問い合わせ先

- [ ] **プライバシーポリシーを公開URLでホストする**（現状はドラフトのみで未ホスト。詳細は下記「提出前に差し替えが必要な箇所」参照）
- [ ] Play Console の「アプリのコンテンツ」→「プライバシーポリシー」欄にそのURLを登録
- [ ] 開発者向け問い合わせ先（メールアドレス）をPlay Consoleの登録情報に設定

### 9. 最終確認

- [ ] `npx tsc --noEmit` / `npx vitest run` / `npx expo lint` が現在の基準値通りであることを確認（`CLAUDE.md`の「現在の基準値」セクション参照。ドキュメント作業なので通常はコード側に影響しないはずだが、他エージェントの並行作業とのコンフリクトが無いか確認する目的で実行してもよい）
- [ ] 実機またはエミュレータでリリースビルドをインストールし、購入・復元・広告表示・Pro機能解放を一通り確認
- [ ] ストア掲載情報のプレビュー画面で6言語すべての表示崩れが無いか確認

## 要確認まとめ（本ドキュメントで断定を避けた項目）

1. スクリーンショットの正確な枚数上限・最小/最大解像度・アスペクト比の最新値（Play Consoleの現行UIで直接確認）
2. AdMob・RevenueCatそれぞれが収集する具体的なデータ項目とData safetyフォームでの正確な申告区分（各社の公式Data safety記入ガイドを最終確認）
3. `POST_NOTIFICATIONS`権限が実際に使われているか（コード内に送信ロジックが見当たらなかった）
4. このプロジェクトのGoogle Playデベロッパーアカウントの作成日（2023年11月13日より前か後かで14日間クローズドテストの要否が変わる）
5. Shipaton 2026公式ルールにおけるデモ動画の長さ上限（2分と3分の情報が交錯している。`docs/market-research-2026-09.md`第7節で既知の課題）
